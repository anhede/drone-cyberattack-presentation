Swedish Openness vs. Security

Openness

  • Research data shared openly
  • Drives innovation & collaboration
  • Public personal data

Risk

  • Easier for espionage
  • State-sponsored threats
  • Industrial spying
Real example: A neighbor in their building is under espionage investigation — IT-Total implemented physical security measures

Speed, Cost & "Good Enough"

100% security is impossible

Business sells speed and features

Engineers want perfect — customers won't pay

The Challenge of Selling Security

300kr

Microsoft 365 / user / month

Clear value

100kr

Security / user / month

Hard to justify

Nordic cyberattack cost: 30-50M SEK
Security at 1M/year = betting you won't be attacked for 30-50 years

ISO27001 & NIS2 in Practice

ISO27001: minimum bar, not security guarantee

Example: Requires password policy, but doesn't specify strength
Even 21+ character passwords have been cracked

NIS2: Forces action on security "debt"

Problem: Companies want certification, not continuous improvement

Real Case: CEO Laptop Attack

Attack Timeline

1. CEO's laptop downloads suspicious packets at 2:00 AM
2. Payloads change RDP sessions, scan for vulnerabilities
3. Attacker creates fake accounts: "backup", "frontdesk", "service desk"
4. Prevention software blocks running script
5. Attacker gets angry, downloads anti-virus disabler tool
6. System isolates laptop automatically

What Could Have Happened

CEO had always-on VPN access to ALL company files

Automation saved the company

Career Advice

Graduates lack: experience with messy, real-world scenarios

"If there was a manual, it would already be automated"

Get comfortable with ambiguity

Build experience:

  • Home labs
  • CTFs
  • Certifications

Key Takeaways

"Good enough" beats "perfect but late"

Standards = minimum, not security guarantee

Embrace ambiguity
