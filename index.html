What is Software Redundancy?

Improve reliability in critical systems

Software does not degrade with time.
- Can't swap-out "aging" software

Software can fail due to design flaws.
- Can't add more "identical" software

Requires different approaches than hardware redundancy

Single-version

Only one software component is developed.

VS

Multi-version

Multiple independently developed software components

Checkpoint & Restart

Design Faults

Not random, and not due to decay

Always present, but only manifest under specific conditions

Lessons Learned

There are ways to add redundancy in software

Single-version software cannot reliably protect against design faults

Diversity is key for multi-version software

While developers may sit far away from hardware, we must be aware of our contribution to safety and reliability
